# AI 상세페이지 4단계 프로토타입: 데이터 반영과 API 검토

기준일: 2026-09-11. 아래는 명세를 읽고 정리한 FE 연동안이다. 실제 서버 호출·인증·저장은 아직 연결하지 않았으며, API 항목의 현재 상태는 `예정`이다. 동작 여부를 검증한 문서는 아니다.

## 1. 이번 화면 반영 범위

작품 정보 입력 → 생성 중 → 초안 확인·편집 → 최종 결과 확인의 네 단계가 본 작업 흐름이다. 이번 변경은 최종 결과의 비어 있던 상품 정보에 시연 값을 넣는 작업과 API 검토이며, 실제 생성 API 연결 및 기존 홈 제거는 포함하지 않는다.

최종 결과는 **편집한 상세페이지 JSON 본문 + 별도 상품·장인·옵션 데이터**를 조합한다. 아래 상품 정보는 AI가 추론하거나 JSON 본문을 덮어쓰는 값이 아니라 노션에 정한 시연 데이터다. 화면에도 시연용 정보임을 표시한다.

| 화면             | 반영값                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 소재             | 백자, 옻칠, 자개                                                                                                                            |
| 규격 / 중량      | 85 × 85 × H65mm / 180g                                                                                                                      |

문서에 없는 작가 사진·리뷰·A/S 연락처·보증 및 반품 정책 등은 임의 생성하지 않는다. 입력/JSON에서 가져온 작품명·이미지·본문은 그대로 사용한다. 옵션의 가산액은 수량별로 적용하는 시연 계산이며 실제 결제 금액은 향후 서버 계산이 기준이다.

## 2. 화면별 필요한 API

로그인한 `ARTISAN` 사용자와 유효한 access token이 전제다. 별도 로그인 화면을 이 프로토타입에 만들지 않아도, 기존 인증 세션 또는 BE가 제공하는 테스트 로그인 환경은 있어야 한다. 배포 코드에 공용 토큰을 넣지 않는다.

| 시점           | API                                                                | 용도와 판정                                                                         |
| -------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| 사진 선택      | `POST /api/images/presigned-url`                                   | 사진별 imageId와 WebP variant별 업로드 URL 발급. 기존 경로 사용                     |
| 업로드         | `PUT {presignedUrl}`                                               | 브라우저에서 S3로 실제 파일 전송. URL 발급만으로 업로드가 완료되는 것은 아님        |
| 상품 ID 준비   | `POST /api/products`                                               | 생성 API의 productId를 얻는 현재 경로. 다수 필수값 문제는 아래 참고                 |
| AI 초안 만들기 | `POST /api/content/products/{productId}/generations`               | `images`, `productName`, `howMade`, `careTips` 전달. `202`와 generationId 반환      |
| 생성 중        | `GET /api/content/products/{productId}/generations/{generationId}` | 생성 상태 폴링. 완료 시 결과 조회, 실패 시 오류·재시도 표시                         |
| 초안 열기      | `GET /api/content/products/{productId}/contents`                   | 결과와 contentId 조회. 현재 응답 형식 보완 필요                                     |
| 수정 완료      | `PATCH /api/content/products/{productId}/contents/{contentId}`     | 편집한 문서 저장. 성공 후 최종 결과로 이동. 현재 요청/응답 형식 보완 필요           |
| 최종 결과      | 별도 API 없이 저장한 문서 + 상품·장인 데이터 조합                  | 현재 프로토타입은 노션 더미 사용. 서버 복원 시에는 작성자용 비공개 상세 조회가 필요 |

생성 요청은 완성 JSON을 바로 반환하지 않는다. **요청(202) → 상태 조회 → 완료 → 결과 조회** 순서다. FE 폴링 간격은 예를 들어 2~3초부터 시작하되 BE와 합의한다. `PROCESSING` 중 실제 진행률이 없다면 임의의 %를 표시하지 않는다.

인증이 새로 필요할 때는 `POST /api/member/login`, 만료 시 `POST /api/member/token/refresh`를 기존 인증 정책에 맞춰 사용한다. 서버에서 장인 정보를 받을 때는 `GET /api/member/artisans/me` 또는 공개 장인 조회를 사용할 수 있다. 더미를 쓰는 이번 최종 화면에서는 장인 조회가 필수는 아니다.

## 3. BE와 먼저 맞춰야 할 사항

### 필수: 조회·저장에서 기존 JSON 전체 보존

[결과 조회](https://app.notion.com/p/6b1ecddcc9cb822fb8e90143642e9c08)와 [문단 일괄 수정](https://app.notion.com/p/535ecddcc9cb825c8bd5815e97cd9f92)은 현재 `blocks`와 `h2/p/img/video` 중심이다. 현재 편집기가 쓰는 `schemaVersion`, `canvasWidth`, `root`, 중첩 `children`, `style`, 노드 `id`를 보존하는 필드가 명시되어 있지 않다. 이를 평탄한 블록으로 바꾸면 특징 카드·표·배치·서식이 사라질 수 있다.

**요청할 변경:** 경로는 유지하고, 결과 조회 및 수정 요청/응답에 기존 v2 JSON을 담는 `document` 필드를 지원한다. 문서 구조 자체는 유지한다. API 바깥의 `contentId`, `productId`, `version`, `status` 등은 그대로 사용한다. 서버와 FE 모두 합의한 요소·스타일만 검증하고 렌더링한다.

이미지는 문서의 `props.imageId`를 유지하고, 응답에 `imageId → URL·width·height·alt`가 연결되는 `assets` 또는 동등한 이미지 목록이 필요하다. BE의 `variants`를 FE 어댑터에서 StudioAsset으로 변환할 수 있다. 현재 수정 요청의 `imageUrl`만으로는 소유권·원본 ID·variant 연결을 보존하기 어렵다. Presigned URL은 짧은 수명의 **업로드 주소**이며 영구 표시 URL로 저장하지 않는다.

### 필수: 새 제작 시 productId 확보 방법

[상품 등록](https://app.notion.com/p/0b8ecddcc9cb8320bfb281808b293486)은 작품명·이미지만으로 호출할 수 없다. 가격, 모델명, 규격, 소재, 구성, 제조자, 원산지, A/S 연락처, 보증정책, 재고, 제작일수, 판매 옵션 등의 필수값을 요구한다. 이번 더미에도 모델명·A/S 연락처·보증정책·재고 등은 없다.

- **이번 연동 시연 권장:** BE가 완성된 테스트 상품을 사용자별 또는 작업별로 준비해 유효한 productId를 제공한다. 동시 사용자가 같은 상품에 덮어쓰지 않도록 분리한다. 더미 화면 값을 등록 API 전체 요청으로 간주하지 않는다.
- **새 작품 입력만으로 시작하는 실제 흐름:** 필수값을 최소화한 초안 등록 방식 또는 생성 요청에서 초안 상품까지 생성하는 방식을 합의한다. 기존 상품 등록의 필수 필드를 FE에서 거짓 값으로 채우지 않는다.

### 필수: generationId와 결과 contentId 연결

[상태 조회](https://app.notion.com/p/ff3ecddcc9cb83a8be9f81a989dc3f9a)는 완료 여부만 있고 contentId가 없다. 결과 조회도 여러 버전의 배열이며 generationId가 없다. 재생성·동시 요청 시 어느 결과인지 구분하기 어렵다.

완료 응답에 `contentId`를 넣거나, 결과 조회에서 generationId로 정확히 선택할 수 있는 계약이 필요하다. 상태의 전체 enum, 실패 시 errorCode/message, `completedAt: string | null`, 최대 대기·재시도 규칙도 확정한다. 실패한 생성 POST를 무조건 자동 반복하지 않는다.

### 명세 정리: 사진 수·형식·관리법

[생성 요청](https://app.notion.com/p/44aecddcc9cb826a987201c4dc7d0d52) 설명은 사진 **3~12장**, JPG/PNG, 관리법 **선택**이다. 요청 표에서는 `careTips`가 **필수**로 적혀 있다. 현재 FE는 사진 **1~12장**, JPG/PNG/WebP, 관리법 선택이다.

- 1장 시연도 필요하면 생성 최소 사진 수를 1장으로 허용하도록 요청하거나 FE를 3장 필수로 맞춘다.
- careTips의 생략/빈 문자열/null 허용 중 하나를 확정한다.
- 업로드 시 WebP 320w/640w/1280w로 변환하는 흐름과 생성 API 설명의 원본 이미지 형식 제한을 구분한다.
- Presigned 요청의 sourceWidth/sourceHeight에는 변환 전 원본 크기를 전달한다. 3종 업로드 성공 뒤 generation 요청에 imageId 목록을 전달한다.

### 서버 복원 시: 비공개 최종 미리보기 조회

[공개 상품 상세](https://app.notion.com/p/fbbecddcc9cb82199b0801e029e3d498)는 DRAFT 상품이 항상 404라고 명시되어 있다. 게시 전 최종 확인에 이 공개 API를 사용하면 안 된다.

지금은 편집 상태와 더미 상품 정보를 그대로 전달하면 추가 API가 없다. 새로고침·다른 기기에서 서버 상태를 복원하려면 소유자만 접근하는 비공개 상품 상세 조회를 제공하거나, 인증된 콘텐츠 조회에 필요한 상품 정보도 함께 반환하도록 합의한다. 공개 API의 DRAFT 노출 제한을 풀 필요는 없다.

## 4. 더미값과 실제 상품 API의 대응

| 더미값                               | 기존 필드 또는 확인점                                                                                                                                                         |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본가·제작기간·배송비·무료배송 기준 | `price: 89000`, `productionPeriodDays: 14`, `shippingFee: 3000`, `freeShippingThreshold: 100000`                                                                              |
| 규격·구성·원산지                     | `size`, `components[]`, `countryOfOrigin`                                                                                                                                     |
| 소재 `백자, 옻칠, 자개`              | `material`은 코드로 정의됨. 코드와 복수 소재 표시 문구의 매핑을 합의                                                                                                          |
| 필수 세트·선물 포장                  | `optionGroups`의 `REQUIRED`, `OPTIONAL`, `choices[].priceDelta` 사용 가능. 필수 stock 및 실제 ID는 BE 제공                                                                    |
| 중량·용도·상품 인증 문구             | `weight` 및 해당 표시값이 상품 상세 DTO에 직접 명시되어 있지 않음. `purposeTags`는 용도와 유사하나 문구 동일성은 별도 확인. 추가 필드/명세 또는 상품 상세 표시 항목 구조 합의 |
| 제조 `대한민국`                      | 문서 값은 국가이므로 `countryOfOrigin`으로 매핑. `manufacturer`(제조자)는 별도 데이터 필요                                                                                    |
| 김영수·전승자 구분·분야·소개         | `artisanName`, `certificationLevel`, category 표시명, `introduction`/`bio` 조합. 공방명 businessName을 작가 개인 이름으로 대체하지 않음                                       |
| 제작 이야기                          | 상품 취재 `story` 또는 명시적인 상품 서사 필드 필요. 작가 공통 bio와 구분                                                                                                     |

`POST/PATCH /api/content/products/{productId}/interview`는 별도 취재 입력을 저장할 때 쓰는 API다. 지금 generation 요청이 howMade/careTips를 직접 받으므로 매번 interview도 먼저 호출해야 한다고 단정하지 않는다. BE에 사전 등록 의존성 여부를 확인한다.

## 5. 네 화면 범위에서 제외할 API

최종 결과를 보는 것까지라면 구매·장바구니·주문·결제·리뷰·문의·추천·홈 목록 API는 필요 없다. 초안의 텍스트·색상·순서 변경은 FE 상태에서 처리하고 수정 완료 시 한 번 저장하면 된다. 필요 시 초안 저장은 같은 PATCH를 쓴다.

최종 확인은 실제 게시와 다른 단계다. 공개 게시까지 범위를 넓히는 경우에만 사실확인·사진일치 확인 후 [콘텐츠 승인](https://app.notion.com/p/1f2ecddcc9cb82fa98ab81f41fbf5eb9) → [상품 게시](https://app.notion.com/p/f35ecddcc9cb82cf99f2015e668bef46)를 추가한다. 단순히 수정 완료를 눌렀다는 이유로 두 확인 값을 자동 true로 보내지 않는다.

## 6. AI·BE 팀에 전달할 핵심

> FE 프로토타입 범위는 작품 정보 입력 → 생성 중 → JSON 초안 편집 → 최종 결과 확인입니다. 상품 기본정보·옵션·장인 소개는 시연 더미로 채웁니다. 기존 AI v2 JSON 형식은 유지하되, BE의 결과 조회 및 수정 API가 document 전체와 imageId에 대응하는 이미지 정보를 보존할 수 있어야 합니다. 연동을 위해 테스트 상품 ID/ARTISAN 인증 환경, generationId와 contentId의 대응, 생성 실패 상태, careTips 선택 여부 및 사진 최소 수를 확정해 주세요. 이번 범위에 상품 게시·구매 API는 필요하지 않습니다.
