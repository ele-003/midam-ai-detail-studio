# AI 상세페이지 스튜디오 이식 및 디자인 시스템 적용

> 실행: executing-plans 스킬로 현재 작업에서 순차 진행한다.

**목표:** 사용자가 승인한 기존 프로토타입 이식 → 공통 컴포넌트 적용 → 편집·저장·미리보기 검증을 완료한다.

**설계:** `src/components/detail-studio/`에 작업실과 제작 경로가 공유하는 스튜디오 모듈을 배치한다. `/`는 작업실, `/seller/products/new`는 입력·생성·편집·결과 경로로 유지한다. 공용 UI와 전역 토큰은 새 저장소의 구현을 사용한다. AI 문서 내부에는 독립된 기본 타이포그래피를 지정하고 JSON의 스타일 값을 그대로 적용한다.

**제약:** 기존 inline-editor 폴더를 수정하지 않는다. npm만 사용한다. JSON 규격·검증과 localStorage 키/데이터 형식을 유지한다. 실제 AI·서버 게시 연동은 이번 범위에 포함하지 않는다. 새 개발 화면은 3002 포트에서 확인한다. 저장 데이터는 브라우저 출처에 속하므로 3001의 데이터가 3002로 자동 이동하지 않는다.

## 1. 기존 흐름 이식

- [x] 새 저장소의 기본 테스트 통과 확인.
- [x] 기존 `studio-home.spec.ts`를 먼저 옮겨 새 저장소에 작업실이 없어서 실패하는지 확인.
- [x] 사용 중인 ContractStudio/ConvertedPreview/StudioInput/InlineText/ProductDetailView 및 JSON 검증·편집·저장 모듈을 복사한다. 기존의 별도 legacy 편집기는 이식하지 않는다.
- [x] 자동차·금속·나전 예시와 참조 이미지를 public 경로 그대로 복사한다.
- [x] 두 라우트에서 이식한 진입 컴포넌트를 사용하고 기존 편집·가져오기 테스트를 함께 이식한다.

## 2. 제작 도구 디자인 통일

- [x] 공통 Button의 variant/size를 명시하고 `.cs-button`의 강제 시각 스타일을 제거한다.
- [x] 작품명은 InputField로 변경한다. 긴 글/JSON은 해당 화면의 TextareaField로 구성해 공통 입력 토큰·레이블·오류 연결을 적용한다.
- [x] 홈 CTA/필터와 편집 툴바는 Button, 상태는 Badge, 경로는 Breadcrumb, 저장 알림은 Toast를 사용한다.
- [x] 공유 StudioHeader를 사용하고 임의 색·텍스트 크기를 semantic token으로 치환한다. 드래그 및 색상 선택은 기존 동작을 유지한다.
- [x] 제작 단계 표시는 기존 4단계를 유지한다. 공통 Stepper는 수량 조절 컴포넌트이므로 사용하지 않는다.
- [x] JSON 본문 기본 글꼴/자간/행간이 편집 화면과 최종 화면에서 같도록 경계를 지정한다.

## 3. 검증 및 실행

- [x] E2E로 입력→생성→편집→최종확인→게시, JSON 파일/텍스트 가져오기, 표·카드·문구, 드래그·색상·실행취소·저장복원, 모바일 넘침을 확인한다.
- [x] 편집/최종 JSON 본문의 계산된 스타일을 비교하는 회귀 검증을 추가한다.
- [x] typecheck, lint, test, build를 실행한다. 변경 파일은 Prettier로 정리한다.
- [x] 3002 화면 스크린샷을 확인하고 사용 방법과 저장/AI 연동 범위를 README에 기록한다.
